# Sources

A source connects a model to where its rows live. You bind each model with `model.from(source)` and pass the result to `sysone()`. The core plans every query, applies access rules, and pages. The source only runs the plan against its database.

| Source | Package | Databases | Checks columns at compile time |
|---|---|---|---|
| `memory(rows)` | `sysonejs` | none, rows live in the process | with `memory<Row>()` |
| `pg(pool, table)` | `@sysonejs/sql` | Postgres through `pg` | no |
| `mysql(pool, table)` | `@sysonejs/sql` | MySQL through `mysql2` | no |
| `drizzle(db, table)` | `@sysonejs/drizzle` | Drizzle on Postgres or MySQL | yes |
| `prisma(delegate)` | `@sysonejs/prisma` | Prisma on Postgres. A MySQL option exists but is untested. | yes |
| `mongo(collection)` | `@sysonejs/mongo` | MongoDB | yes |

Every source runs the same test suite, `testSource` from `sysonejs/source`. See [Writing a source](./writing-a-source.md).

All examples on this page use this model:

<!-- file: model.ts -->
```ts
import { defineModel } from "sysonejs"
import { z } from "zod"

export const category = defineModel({
  name: "category",
  schema: z.object({
    id: z.number().int(),
    name: z.string().min(1).max(80),
    parentId: z.number().int().nullable(),
    active: z.boolean(),
    createdAt: z.date(),
  }),
  write: ["name", "parentId", "active"],
  search: ["name"],
  filter: ["parentId", "active", "createdAt"],
  sort: ["name", "createdAt"],
  relations: { parent: { model: "category", key: "parentId" } },
  access: () => ({ read: true, create: true, update: true, delete: true }),
})
```

`createdAt` is not in `write`, so the database fills it. The SQL tables below give it a default.

## Memory

`memory(rows)` keeps rows in an array in the process. Use it for prototypes, demos, and tests. Data is lost on restart.

<!-- file: memory.ts -->
```ts
import { memory, sysone } from "sysonejs"
import { category } from "./model.ts"

const rows = [{ id: 1, name: "Fruit", parentId: null, active: true, createdAt: new Date() }]

export const api = sysone({ basePath: "/api", models: [category.from(memory(rows))] })
```

- Each bind copies the rows, so the array you pass in is not changed.
- A new row with a number or bigint id gets the next number after the largest id. A new row with a string id gets `crypto.randomUUID()`.
- Fields that the client does not send and that have no Zod default stay empty. In the model above, rows created through the API have no `createdAt`.
- `memory<{ id: number; name: string }>()` with a row type checks the columns like a database source.

## Postgres with `pg`

Install the package and the driver:

```sh
npm install @sysonejs/sql pg
```

Create the table:

<!-- file: pg.sql -->
```sql
CREATE TABLE categories (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  parent_id int,
  active boolean NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

Bind the model:

<!-- file: pg.ts -->
```ts
import { pg } from "@sysonejs/sql"
import { Pool } from "pg"
import { sysone } from "sysonejs"
import { category } from "./model.ts"

const pool = new Pool({ connectionString: process.env.DATABASE_URL })
const columns = { parentId: "parent_id", createdAt: "created_at" }

export const api = sysone({ basePath: "/api", models: [category.from(pg(pool, "categories", { columns }))] })
```

| Argument | Meaning |
|---|---|
| `pool` | A `pg` `Pool` or `Client`. |
| `table` | The table name. Use `"schema.table"` for a table outside the default schema. |
| `options.columns` | Maps a field to a column name when they differ. Fields not listed use their own name. |

## MySQL with `mysql2`

```sh
npm install @sysonejs/sql mysql2
```

<!-- file: mysql.sql -->
```sql
CREATE TABLE categories (
  id int AUTO_INCREMENT PRIMARY KEY,
  name varchar(80) NOT NULL,
  parent_id int,
  active boolean NOT NULL,
  created_at datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
);
```

<!-- file: mysql.ts -->
```ts
import { mysql } from "@sysonejs/sql"
import { createPool } from "mysql2/promise"
import { sysone } from "sysonejs"
import { category } from "./model.ts"

const pool = createPool({ uri: process.env.DATABASE_URL, timezone: "Z" })
const columns = { parentId: "parent_id", createdAt: "created_at" }

export const api = sysone({ basePath: "/api", models: [category.from(mysql(pool, "categories", { columns }))] })
```

`mysql()` takes the same arguments as `pg()`, with a pool from `mysql2/promise`. Set `timezone: "Z"` on the pool so that `datetime` columns are read and written as UTC.

## Drizzle

```sh
npm install @sysonejs/drizzle drizzle-orm
```

The model's field names must match the keys of the Drizzle table, not the database column names. Drizzle maps them:

<!-- file: drizzle-pg.ts -->
```ts
import { drizzle } from "@sysonejs/drizzle"
import { drizzle as connect } from "drizzle-orm/node-postgres"
import { boolean, integer, pgTable, text, timestamp } from "drizzle-orm/pg-core"
import { sysone } from "sysonejs"
import { category } from "./model.ts"

const categories = pgTable("categories", {
  id: integer().primaryKey().generatedByDefaultAsIdentity(),
  name: text().notNull(),
  parentId: integer("parent_id"),
  active: boolean().notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
})

const db = connect(process.env.DATABASE_URL!)

export const api = sysone({ basePath: "/api", models: [category.from(drizzle(db, categories))] })
```

The same source works with a MySQL Drizzle database:

<!-- file: drizzle-mysql.ts -->
```ts
import { drizzle } from "@sysonejs/drizzle"
import { sql } from "drizzle-orm"
import { drizzle as connect } from "drizzle-orm/mysql2"
import { boolean, datetime, int, mysqlTable, varchar } from "drizzle-orm/mysql-core"
import { createPool } from "mysql2/promise"
import { sysone } from "sysonejs"
import { category } from "./model.ts"

const categories = mysqlTable("categories", {
  id: int().autoincrement().primaryKey(),
  name: varchar({ length: 80 }).notNull(),
  parentId: int("parent_id"),
  active: boolean().notNull(),
  createdAt: datetime("created_at", { mode: "date", fsp: 3 }).notNull().default(sql`(now(3))`),
})

const db = connect(createPool({ uri: process.env.DATABASE_URL, timezone: "Z" }))

export const api = sysone({ basePath: "/api", models: [category.from(drizzle(db, categories))] })
```

- `.from()` fails to compile if the table lacks a key for a model field. At startup, a missing column throws `@sysonejs/drizzle: model "category" has no column for field "..."`.
- Use `bigint({ mode: "bigint" })` for bigint fields and `{ mode: "date" }` for MySQL dates, so that Drizzle returns `bigint` and `Date` values.

## Prisma

```sh
npm install @sysonejs/prisma
```

Field names must match the Prisma model's field names. Use `@map` for different column names:

<!-- file: schema.prisma -->
```prisma
generator client {
  provider = "prisma-client"
  output   = "./generated/prisma"
}

datasource db {
  provider = "postgresql"
}

model Category {
  id        Int      @id @default(autoincrement())
  name      String
  parentId  Int?     @map("parent_id")
  active    Boolean
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz

  @@map("categories")
}
```

Pass the model's delegate, such as `db.category`, to `prisma()`:

<!-- file: prisma.ts -->
```ts
import { PrismaPg } from "@prisma/adapter-pg"
import { prisma } from "@sysonejs/prisma"
import { sysone } from "sysonejs"
import { PrismaClient } from "./generated/prisma/client.ts"
import { category } from "./model.ts"

const db = new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) })

export const api = sysone({ basePath: "/api", models: [category.from(prisma(db.category))] })
```

| Option | Default | Meaning |
|---|---|---|
| `provider` | `"postgresql"` | `"postgresql"` makes search case-insensitive with Prisma's `mode: "insensitive"`. `"mysql"` leaves it out, because Prisma does not support it on MySQL. The MySQL option is untested. |

## MongoDB

```sh
npm install @sysonejs/mongo mongodb
```

The model's id field is stored as `_id`. Every other field is stored under its own name.

<!-- file: mongo.ts -->
```ts
import { mongo } from "@sysonejs/mongo"
import { MongoClient } from "mongodb"
import { sysone } from "sysonejs"
import { category } from "./model.ts"

interface CategoryDoc {
  _id: number
  name: string
  parentId: number | null
  active: boolean
  createdAt: Date
}

const client = new MongoClient(process.env.DATABASE_URL!)
const categories = client.db().collection<CategoryDoc>("categories")

export const api = sysone({ basePath: "/api", models: [category.from(mongo(categories))] })
```

- With a number or bigint id, a new document gets the largest numeric `_id` plus one. If two inserts race for the same id, the source retries.
- With a string id and no value, MongoDB creates an `ObjectId`, and the API sends it as a 24-character hex string.
- MongoDB has no column defaults. A field like `createdAt` that is not in `write` stays empty on new documents. Give it a Zod `.default()` and add it to `write`, or set it in the [create rule](./access.md#create-stamps-the-scope-into-the-row).
- If the model has a bigint field, the source reads 64-bit integers as `bigint`.

### ObjectId fields

The `objectIds` option lists fields whose 24-character hex strings are stored as `ObjectId`. It defaults to the id field, so a string id over an `ObjectId` `_id` works with no options. Reads always turn an `ObjectId` into its hex string.

<!-- file: mongo-objectid.ts -->
```ts
import { mongo } from "@sysonejs/mongo"
import { MongoClient, type ObjectId } from "mongodb"
import { defineModel, sysone } from "sysonejs"
import { z } from "zod"

interface UserDoc {
  _id: ObjectId
  name: string
}

const user = defineModel({
  name: "user",
  schema: z.object({ id: z.string(), name: z.string() }),
  search: ["name"],
  access: () => ({ read: true }),
})

const users = new MongoClient(process.env.DATABASE_URL!).db().collection<UserDoc>("users")

export const api = sysone({ basePath: "/api", models: [user.from(mongo(users))] })
```

To store more fields as `ObjectId`, list them together with the id. In 0.1.0 the option's type expects the document's keys, such as `_id`, but the source compares model field names, such as `id`. Passing `_id` compiles, but then the id is no longer converted and every get by id returns `404`. Until this is fixed, pass the model field names with a cast:

<!-- file: mongo-objectid-more.ts -->
```ts
import { mongo } from "@sysonejs/mongo"
import { MongoClient, type ObjectId } from "mongodb"
import { defineModel, sysone } from "sysonejs"
import { z } from "zod"

interface MemberDoc {
  _id: ObjectId
  name: string
  teamId: ObjectId
}

const member = defineModel({
  name: "member",
  schema: z.object({ id: z.string(), name: z.string(), teamId: z.string() }),
  filter: ["teamId"],
  access: () => ({ read: true }),
})

const members = new MongoClient(process.env.DATABASE_URL!).db().collection<MemberDoc>("members")

export const api = sysone({ basePath: "/api", models: [member.from(mongo(members, { objectIds: ["id", "teamId"] as never }))] })
```

Without `teamId` in `objectIds`, a filter on `teamId` compares a string with an `ObjectId` and matches nothing.

## Caveats by database

| Database | Notes |
|---|---|
| All | Queries select only the model's fields. Updates and deletes put the access rule in the same statement as the write. |
| Postgres | Search uses `ILIKE`. Keyset paging uses a row comparison when all sort keys have the same direction. |
| MySQL | Search uses `LIKE`, so case-insensitivity follows the column's collation. The default `utf8mb4` collations ignore case. After an insert or update, the source reads the row back with a second query. |
| Prisma | An update runs `updateMany` with the access rule, then reads the row back with `findFirst`. |
| MongoDB | Search uses a case-insensitive regular expression with the term escaped. A `null` filter also matches documents where the field is missing. Inserts and updates do not use transactions. |
| Memory | Data lives in one process. Sorting and filtering scan the whole array. |
