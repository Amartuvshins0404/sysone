# sysone v1 design contract

The synthesized design for the v1 rewrite. Base: arena candidate 1 ("TS-first, types cross the wire, values don't"). Read in this order:

1. `v1-usage.md`. The caller's view. This is the spec.
2. `v1-rationale.md`. Why the shape is what it is.
3. `v1-sketch/*.ts`. Types and signatures. Bodies are `not implemented` with `TODO` pseudocode for the tricky parts.

Where this file and the sketch disagree, this file wins.

## Decisions made after the arena

| Topic | Decision |
|---|---|
| Model with no `access` | Denied for every action. A public read-only model writes `access: () => ({ read: true })`. |
| `include` (belongs-to relations) | In v1. |
| Total count, page numbers | Not in v1. |
| Prisma scoped writes | `updateMany` / `deleteMany` with the scope in `where`, then `findFirst` to read back. Two statements is accepted. |
| SSR, hydration | Not in v1. |

## Grafts from candidate 2 (change the sketch accordingly)

1. **One wire encoding step on the server.** `pick` in `plan.ts` becomes `encodeRow(c, row)`. It keeps only model fields and converts by `FieldSpec.kind`: `bigint` to string, `boolean` from 0/1 to true/false, `date` to ISO string, everything else unchanged. Sources return driver values as they are (no per-adapter fixups, no `exact` flag). `meta.types` lists `date` and `bigint` fields so the client revives them. This fixes the v0 crash when a row has a bigint.
2. **Smarter list reload in the client cache.** On `patch`, a list refetches only if a field that changed (diff of old vs new row) is one the list filters, sorts or searches on. Otherwise the in-place entity update is enough. On `remove`, drop the id from every list with no refetch (keyset cursors survive deletes). On `insert`, refetch the loaded span of that model's mounted lists.
3. **No `@sysonejs/express` package.** `sysonejs/node` exports `nodeHandler(app, { context })` returning `(req, res, next?) => void`. It works as Express middleware and with plain `node:http`. It routes on `req.originalUrl ?? req.url` and strips `app.basePath`, so mount it with `app.use(handler)`. If `req.body` is already parsed (express.json), it uses it; otherwise it reads the stream. Unmatched paths call `next()` or answer 404 when there is no `next`.
4. **Language-neutral conformance.** Wire-level cases live as JSON (`spec/cases/*.json`: request, expected status, expected body shape) with a tiny runner that hits any server URL. Store-level `testSource` stays for adapter authors.

## Done predicate

- Build and typecheck clean for every package and example.
- `testSource` passes for memory, pg, mysql, drizzle (pg and mysql), prisma (pg), mongo, against the Docker DBs in `examples/express/compose.yml`.
- The JSON conformance cases pass over HTTP for the Express/Node handler on Node, and for `fetchHandler` on Bun.
- React hooks pass a headless DOM check against a live server: select with an off-page selected value, include, debounce, load more, patch without refetch, delete without refetch, insert refetch.
- Browser bundle from `examples/web` (a real frontend entry, only react external) is at most 2.6 KB brotli and contains no zod or driver code. v0 baseline: 76.62 KB.
- Type probes: writing a non-`write` field, filtering or sorting outside the allowlists, sorting on a nullable field, an unknown include, and a source missing a column are all compile errors.
- HTTP throughput of a list request is within 5% of a hand-written Express route (3 runs each, spread reported).

## Owner rules for all code

No code comments. Zero runtime dependencies (zod, react, drivers and ORMs are peers). No secrets in files. Reuse existing libraries before writing new ones.
